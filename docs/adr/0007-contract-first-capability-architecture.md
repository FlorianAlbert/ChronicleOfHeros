# Contract-first capability architecture

ChronicleOfHeros organizes product behavior as independently composable capabilities. Each capability exposes exactly one public contracts project containing only transport-neutral interfaces and request/response DTOs, plus one implementation project that owns its domain concepts, application behavior, framework integrations, configuration, and persistence. Consumers reference a capability only through its contracts project. An executable composition host, or the implementation's test project, may additionally reference the implementation solely to invoke its public registration API.

An implementation keeps Domain, Application, Infrastructure, and DependencyInjection as internal layers. Domain has no framework or internal-layer dependencies; Application depends only on Domain, the capability contracts, and private ports it owns; Infrastructure implements those private ports and contains framework integrations; DependencyInjection is the sole internal assembly point. Implementation types are internal unless they are the one registration API, a narrowly necessary composition configuration type, an unavoidable framework-convention type, or belong in the contracts project.

Hosts are composition and transport adapters. They register each installed capability through one self-sufficient registration call, map individual endpoint adapters through dependency injection, and invoke only public capability contracts. They do not implement business workflows or own framework persistence. A dedicated migrations host selects a migration-enabled registration mode through that same one registration call; normal application startup never changes schema state.

The primary test seam is a capability's public contracts plus its registration call. Architecture tests enforce reference direction, internal-layer boundaries, public surfaces, composition roots, and endpoint rules. Framework-surface exceptions require an ADR and a narrow architecture-test allowlist. A shared kernel is prohibited until a stable business concept has genuine shared ownership; introducing one also requires an ADR and a narrow dependency allowlist.

This decision governs capability boundaries without replacing the existing Aspire orchestration, PostgreSQL datastore, Blazor render-mode, same-origin gateway, localization, or Identity security decisions. Those decisions continue to govern their respective concerns.
